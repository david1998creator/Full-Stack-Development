## 2. Root Cause Analysis & Empirical Evidence

### 2.1 Issue 1: Windows UTF-8 BOM Crash in REPL Batch Execution

#### Code Location
`src/persistent_crewai/cli/main.py`, lines 69–76:
```python
69:     if batch:
70:         with open(batch, "r", encoding="utf-8") as f:
71:             lines = f.readlines()
72:         outputs = shell.run_batch(lines)
73:         for out in outputs:
74:             if out:
75:                 click.echo(out)
76:     else:
77:         shell.cmdloop()
```

#### Failure Mechanism
1. On Windows environments, scripts generated by PowerShell (`Out-File -Encoding utf8`, `Set-Content`, or redirects) prepend the standard 3-byte UTF-8 Byte Order Mark (`0xEF, 0xBB, 0xBF`).
2. Python's standard `encoding="utf-8"` codec decodes those bytes into the Unicode character `\ufeff` (Zero-Width No-Break Space) and preserves it at index 0 of the first string read from the file.
3. When `shell.run_batch(lines)` processes the first line (e.g. `\ufeffstatus\n`), `InteractiveREPL.execute_command()` strips leading whitespace but retains `\ufeff`, tokenizing the command verb as `cmd = "\ufeffstatus"`.
4. Because `"\ufeffstatus"` does not match any recognized command verb (`"status"`, `"dashboard"`, etc.), execution falls through to the unknown command handler (`src/persistent_crewai/cli/repl.py` line 256):
   ```python
   return (
       f"Unknown command '{cmd}'. Type 'help' for available commands.\n"
       f"Valid verbs: ask, run task, run <workflow>, status, decisions, milestones, memory, export, import, exit."
   )
   ```
5. `main.py` line 75 invokes `click.echo(out)`. On Windows consoles, standard output defaults to Microsoft code page `cp1252` (or similar regional ANSI encodings).
6. The `cp1252` charmap codec cannot encode Unicode character `\ufeff` (`U+FEFF`), throwing an unhandled exception:
   ```text
   File "C:\Python313\Lib\encodings\cp1252.py", line 19, in encode
       return codecs.charmap_encode(input,self.errors,encoding_table)[0]
   UnicodeEncodeError: 'charmap' codec can't encode character '\ufeff' in position 17: character maps to <undefined>
   ```

#### Reproduction Evidence
Executed empirical reproduction command:
```python
import subprocess, tempfile, os

with tempfile.NamedTemporaryFile('wb', delete=False, suffix='.crew') as f:
    f.write(b'\xef\xbb\xbfstatus\nexit\n')
    fname = f.name

proc = subprocess.run(['crewai-team', 'repl', '--batch', fname], capture_output=True, text=True)
print('returncode:', proc.returncode)
print('stderr:', proc.stderr)
```
Observed verbatim output:
```text
returncode: 1
stderr: Traceback (most recent call last):
  ...
  File "C:\Users\User\.gemini\antigravity\scratch\persistent_crewai_team\src\persistent_crewai\cli\main.py", line 75, in repl
    click.echo(out)
  ...
  File "C:\Python313\Lib\encodings\cp1252.py", line 19, in encode
    return codecs.charmap_encode(input,self.errors,encoding_table)[0]
UnicodeEncodeError: 'charmap' codec can't encode character '\ufeff' in position 17: character maps to <undefined>
```

#### Remediation Solution
Python provides the built-in codec `utf-8-sig`. When reading, `utf-8-sig` automatically checks for and strips the leading BOM if present; if no BOM is present, it reads normal UTF-8 without error.
Changing line 70 of `src/persistent_crewai/cli/main.py` to:
```python
        with open(batch, "r", encoding="utf-8-sig") as f:
```
completely resolves the issue. Tested against both BOM-encoded and non-BOM files:
- With BOM: `lines = ['status\n', 'exit\n']`, executes status dashboard cleanly, `outputs[0].encode('cp1252')` succeeds, exit code 0.
- Without BOM: `lines = ['status\n', 'exit\n']`, identical valid execution.
